### Estudo de Caso 5

1. Liste dois requisitos funcionais.

- O sistema deve permitir cadastrar usuario;

- O sistema deve permitir adicionar catalogo de livros;

2. Liste dois requisitos não funcionais.

- O sistema deve ser hospedado em um servidor local;
 
- O sistema deve estar disponivel 14 horas por dia e 5 dias semanais.
   
3. Qual seria uma consequência de falha? Indique quem seria afetado.

- Perda de dados provocada por uma queda de energia e inoperabilidade do sistema, lesando assim os usuarios.  

4. O sistema é A, B ou C? Apresente evidências do cartão.

- Sistema B. Cadastro de usuarios, catalogo de livros, emprestimos, devolucoes, reservas e multas.

5. Proponha um teste importante e explique o que ele verificaria.

- Teste de Unidade para verificar a funcao especifica na classe cadastrar usuario, onde nao podde permitir um usuario possuir varios cadastros.

6. Cite uma mudança futura que exigiria manutenção ou evolução.

- Adicao de metodo de pagamento de multa via chave pix.

7. Qual nível de rigor de Engenharia de Software é adequado? O que seria excesso ou insuficiência nesse caso?

- Por ser um sistema B nao haveria tanta rigorosidade por nao envolver vidas humanas e processos criticos.
